## Commands (from root `package.json`)

| Task | Command |
| --- | --- |
| Install | `pnpm install` (pnpm 10.32.1 pinned via `packageManager`; Node >= 22) |
| Infra up/down | `pnpm infra:up` / `pnpm infra:down` (docker compose) |
| Migrate / seed | `pnpm db:migrate` (`@specd/db`) / `pnpm db:seed` (`@specd/api`) |
| Dev (both) | `pnpm dev` — parallel `@specd/api` + `@specd/web`; also `dev:api`, `dev:web` |
| Build | `pnpm build` — packages first, then api, then web (order is deliberate) |
| Typecheck | `pnpm typecheck` — builds `packages/*` first, then `pnpm -r typecheck`; without the build step a clean clone typechecks against unbuilt `dist/` and fails (learned in #56) |
| Test | `pnpm test` = `pnpm -r test` + `pnpm cli:test` (`go vet ./... && go test ./...`) |
| Evals | `pnpm eval` — the grading harness in `evals/`; grades, never gates |
| CLI build/install | `pnpm cli:build` → `./bin/specd`; `pnpm cli:install` → `go install` + `scripts/check-cli-path.mjs` |
| Headless pipeline | `pnpm --filter @specd/api loop` |

Verify command for changes: `pnpm typecheck && pnpm test`. CI runs exactly
that on every push and pull request (`.github/workflows/ci.yml`), against a
real pgvector service, and fails the run if the suites that need Postgres
skipped themselves instead of passing.

## Package naming

Workspace packages are scoped `@specd/*` — `@specd/api`, `@specd/web`,
`@specd/runner`, `@specd/db`, `@specd/shared`, `@specd/templates` (the `name`
field in each `package.json`). The root package is plain `specd`.

## Testing

- All six workspace packages define a `test` script running Vitest (root
  devDependency; no `vitest.config` exists anywhere — defaults only). The CLI
  is the one exception: Go's own toolchain.
- Go tests for the CLI run under `cli:test` and are gated by `go vet` first.
- The README states the current suite size; the CI skip-guard
  (`scripts/check-no-skips.mjs`) is what keeps "green" meaning "ran" rather
  than "skipped". The headless `loop` labels model-dependent steps as skipped
  rather than passing them.
- **Tests that need Postgres skip themselves when none is reachable** (gate + webhook tests) — the suite must stay green on a machine with no infra. Preserve that behaviour when adding integration tests.
- README states webhook signatures are tested with real HMAC and App JWTs with real RSA keys, deliberately not mocked. Follow that precedent for signing/verification code.

## TypeScript

`tsconfig.base.json` at the root is the shared base: ES2023, `module` and
`moduleResolution` both `NodeNext`, `strict` plus `noUncheckedIndexedAccess`,
declarations + source maps, and decorator support for Nest. No path aliases —
cross-package imports go through the `@specd/*` workspace names, which is why
`pnpm typecheck` builds `packages/*` first.

## Configuration

- `.env.example` is committed; `cp .env.example .env` and dev defaults work as-is. Keep new variables documented there.
- `.env.example` **is** the authoritative variable set — every variable is
  documented there, in sections, with the reason it exists. Note that
  `SPECD_AI_MODE` is not among them: AI mode lives on a project's AI
  connection (`connections.settings.mode`), and that env var drives only the
  headless loop (`apps/api/src/e2e-loop.ts`).
- Postgres is on **5433** on the host (non-default, to avoid clashing with local installs). It is the only runtime dependency — Redis was removed with the unused queue (`decisions/0008-remove-unused-queue.md`).

## Writing conventions the product itself enforces

These apply to generated content and to knowledge docs in this repo:

- Every design claim is either **cited** or flagged `UNVERIFIED`. A citation that cannot be followed is treated as worse than none.
- Citations are checked against what was actually retrieved, and the result is one of four verdicts, not two. `supported` matched a retrieved chunk. `unsupported` was checked and is wrong — no such doc, or no such section in it. `unknown` could not be checked: the doc is real but never reached the prompt, or holds no indexed content, or the material was cut for budget. An `unknown` keeps its citation *and* carries the caveat, because "I found no evidence" and "no evidence exists" are different answers and only one of them is safe to write into a spec.
- `stale` is a fourth verdict on a different axis. The three above ask how well a citation could be checked; this asks whether what it points at is still true. A claim cited to a passage that describes code which has moved since anyone touched that passage is accurate about the evidence and misleading about the world. It is scoped to the section the stale reference sits in, because one stale reference in a deployment section says nothing about a data-model section.
- Only `supported` claims count toward the grounding metric — a claim a human still has to check is not grounding. Letting a coverage gap inflate it is the metric lying about the thing it exists to measure.
- Skipped work is **labelled as skipped**, never silently passed (the headless `loop` does this for model-dependent steps).
- Money is integer EUR cents — no floats for spend.

## Behavioural rules for agents working in this repo

- Read `knowledge/` before writing code — the reading order lives in `knowledge/README.md` — work from an approved spec, and write what was built back to `knowledge/specs/` in the same PR.
- Never push to a default branch. Work lands on the spec's own branch plus a PR (hosted) or a branch to diff (local mode).
- `packages/templates` ships the `AGENTS.md` / `CLAUDE.md` scaffolds for
  **onboarded** projects. This repo's own `AGENTS.md` is itself a generated
  instance of that template — kept because specd onboarded itself
  (`decisions/0011-specd-develops-specd.md`) — so the template governs here
  too, one meta-level down.
