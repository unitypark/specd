# Glossary — unitypark/specd

> **status: DRAFT — review before trusting.** Generated by specd from a
> read-only repo scan. Claims the agent could not ground in the code are
> marked `UNVERIFIED`. Merging this PR is how you adopt it; edit freely.

Domain terms mined from code and docs. The agent can spot the words; only a
human can confirm what they mean.

| Term | Meaning |
| --- | --- |
| **station** | One of the six fixed pipeline steps (01 Connect … 06 Learn); cannot be added, skipped or removed. |
| **Connect / Ground / Spec / Build / Learn** | Stations 01, 02, 03, 05, 06: register a repo, index it into the knowledge base, draft a cited spec, implement it, file the as-built back into knowledge. |
| **the gate** | Station 04 — mandatory human approval between Spec and Build; enforced server-side, not by convention. |
| **knowledge base / `knowledge/`** | Per-project markdown in git that agents must read before coding; the platform stores only a derived index of it. |
| **UNVERIFIED** | Literal marker on any claim without a checkable citation; the product demotes invented citations to this. |
| **citation** | A reference to retrieved repo content backing a design claim; validated against what was actually retrieved. |
| **spec lifecycle / transition** | State machine over spec states (draft → approved, no reverse); illegal jumps refused. UNVERIFIED — full state list not seen. |
| **supersede** | How a spec is revised: v2 replaces v1 while v1 keeps its original approval stamp; specs are append-only. |
| **approver / actor** | The named human recorded on an approval; a DB CHECK constraint rejects an approved row without one. |
| **EARS** | Requirement-phrasing syntax rendered by `packages/shared`. UNVERIFIED — likely Easy Approach to Requirements Syntax; confirm in code. |
| **rate card** | Per-model token pricing table used to meter run cost in integer EUR cents. |
| **cap** | Spend limit checked before a run starts rather than after it overspends. |
| **subscription_runner** | `SPECD_AI_MODE` value that shells out to a locally logged-in Claude Code CLI instead of using an API key; unavailable to a hosted specd. |
| **loop (`pnpm --filter @specd/api loop`)** | Headless end-to-end exercise of every station over the real HTTP API, reporting pass/skip per station. |
| **VCS adapter** | Abstraction over hosted (GitHub) vs local repos; README calls the hosted/local split one of the two interesting design decisions. UNVERIFIED — no adapter code seen. |
| **local mode** | Repo registered via `specd connect .`; code stays on the machine and output is a branch you diff rather than a PR. |
| **delivery id** | GitHub's per-webhook-delivery identifier, used to deduplicate replayed deliveries. |
| **installation** | GitHub App installation; a webhook is acted on only when repository *and* installation match a registered project. |
| **audience-scoped token** | CLI token carrying an audience claim that authoring/approval routes reject. |
| **device flow** | `specd login` — the CLI cannot mint a token; a human confirms a code at the web app's `/cli-login`. |
